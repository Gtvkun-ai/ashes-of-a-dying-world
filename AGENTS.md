# Repository Instructions

## Visual Direction (Non-Negotiable)

These rules override any aesthetic inference drawn from the project name,
repository name, genre label, or isolated lore terms.

- `Tan Sinh` and `Ashes of a Dying World` describe a narrative tension. They
  are not prompts to make the whole game look ruined, dirty, dark, or dead.
- Beauty, clarity, light, living color, and regeneration are the default visual
  signals. The world may be bright, saturated, peaceful, lush, and beautiful.
- UI and HUD work must feel clean, elegant, readable, alive, and intentionally
  authored. Dark surfaces are allowed for readability, but must not imply rot
  or decay by default.
- Decay is contextual. Use it only when a specific location, story event,
  object, character state, or gameplay state justifies it.
- Never infer brown grading, global desaturation, rust, ash, cracks, erosion,
  distressed edges, or grunge merely from the title.
- Do not make every panel ancient, damaged, mournful, or materially identical.
- Build identity through composition, silhouette, iconography, typography,
  color relationships, spacing, and motion. Decorative deterioration is not a
  substitute for art direction.
- Do not redesign character portraits or character illustrations unless the
  user explicitly requests it.

Core principle:

> The world is beautiful enough that its loss matters.

Before proposing or changing visuals:

1. Read `docs/visual_language_doc.md`.
2. Inspect `docs/world_concept_art.png` and current runtime screenshots.
3. Identify what expresses life, beauty, or renewal in the proposal.
4. If decay appears, name the concrete narrative or gameplay reason for it.
   If the only reason is the title, remove it.
